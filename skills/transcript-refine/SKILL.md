# 转写稿清理与精炼

## 重点

- **先判断用途**：面试清理保留现场证据；课程精炼保留完整教学内容。
- **保护原稿**：默认另存处理结果，保留原稿与可追溯位置。
- **按需加载**：只读取命中的场景细则，清理与复盘分别执行。

## 一、判断场景

优先依据用户明确指定的任务，再看材料目的，最后参考文件名。
不能确定是面试还是课程，且判断会改变删改范围时，先询问；
确认前只做保留原意的分段、标点和明确识别错误修正。

| 用户目的 | 按需读取与处理 |
| --- | --- |
| 面试文稿清理、提高原稿可读性 | [面试清理](references/interview-cleanup.md) |
| 视频或直播课程首次学习、阅读稿或口播稿 | [课程精炼](references/course-refinement.md) |
| 清理面试稿后生成复盘 | 先执行面试清理，再交给 `document-writing` |
| 仅分析面试或生成复盘 | 交给 `document-writing`，不重复清理可读原稿 |

面试官与候选人的对话不套课程教学规则。
只有明确要求生成复盘，或复盘任务确实需要改善原稿可读性时，
才衔接对应流程；用户只要清理时，到清理结果交付为止。

## 二、共同清理规则

- 按原始顺序整理自然段、标点、断句和换行；保留说话人及已有时间戳。
- 根据上下文修正明确的识别错字、拼写、缩写、技术术语和专有名词，
  同一概念统一写法。不能确定的词保留或标记待核对。
  用户澄清术语、事实或说话人后，直接更新对应文字与标签，移除已解决的标记；
  清理稿只保留整理后的对话，不追加“由本人确认”、核对清单或纠错经过。
  用户明确要求过程记录时单独提供，真实的错误判断和犹豫仍按场景细则保留。
- 区分识别错误与讲述者真实说错的内容。
  面试中的知识错误、犹豫和逻辑缺口按面试细则保留；
  课程中依据资料校正知识的规则只在课程模式生效。
- 段落围绕一个说话主题，主题或说话人变化时分段。
  普通正文源码按约 80 个显示列自然换行；
  不为排版拆开术语、时间戳或破坏原始问答关系。
- 材料中没有依据的事实、数字、观点、个人经历和说话人身份不补造。
  关键内容听不清或缺失时指出缺口，不猜测成完整回答。

## 三、文件与交付

- 新建处理稿或目录前，读取 `project-structure` 的统一命名规则，
  由它分配目标目录的排序编号，本 skill 只确定用途后缀。
  默认同目录保存，名称主体分别为 `<原名>-清理.md`、
  `<原名>-阅读稿.md`、`<原名>-口播稿.md`。
  `<原名>` 去掉原扩展名与已有排序前缀；不复制来源编号作为输出编号。
  用户明确指定路径、文件名或要求在原文件清理时，遵循其请求。
- 默认保留原稿；目标文件已存在时，使用不冲突的新文件名，
  除非用户明确要求更新该文件。
- 用原稿时间戳、原始行范围或已有段落编号保留定位依据。
  位置无法可靠获取时说明限制，不把清理后的行号冒充原稿行号。
- **面试清理稿属于证据整理**：不调用成文模板，
  不额外加入顶层标题、重点、评分或复盘章节。
- **课程稿属于成文材料**：先完成课程内容精炼，
  再读取 `document-writing` 的通用规则与课程学习材料细则组织 Markdown。
  两个 skill 同在 `content-skills` 中；若目标环境缺少后者，
  交付已完成的精炼内容并说明未执行统一排版的限制。
- 面试清理后需要复盘时，向 `document-writing` 交接原稿路径、
  清理稿路径、定位依据、仍不确定的片段及用户已提供的上下文和输出格式。
  用户只要清理时，不索要简历或 JD。

## 四、自检

- 场景是否依据用户目的判断，且只加载了相关细则？
- 识别纠错是否有依据，原意、顺序和已有说话人是否保留？
- 面试证据是否保真，课程知识是否完整，是否发生跨场景删改？
- 是否按请求交付并保护原稿，定位是否真实？
- 是否仅在用户要求复盘时进入复盘，未向清理稿加入分析结论？
