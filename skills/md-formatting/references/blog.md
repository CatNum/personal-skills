# 博客文档细则

适用于分享观点、经历、实践过程或故事的文章；同时遵循主 `SKILL.md` 的通用格式。

## 内容与组织

- `## 重点` 提炼作者的核心观点、关键经验或结论，不写成需求清单。
- 正文可以按“背景 → 经历或论证 → 收获”展开，也可以按时间线、问题推进或其他适合读者理解的顺序组织。只有原文支持的部分才设标题。
- 例子、引用、结果和反思保留原有语气及确定程度；来源未证实的判断不要改写为事实。
- 标题仍遵循通用编号规则，但章节名称应服务文章表达，不强制使用“目标”“范围”“验收”等规格书标题。

## 场景检查

个人踩坑经历只有问题、尝试和反思时，可用这些内容组织正文；不要补产品范围、版本计划或尚不存在的技术方案。
