# 课程学习材料细则

## 重点

- **目的**：将已精炼的课程知识组织为可独立学习的阅读稿或口播稿。
- **内容来源**：转写纠错、删减、教学解释与证据增强由 `transcript-refine` 维护。

## 一、入口与结构

输入仍是原始课程转写稿时，先使用 `transcript-refine` 的课程模式。
已提供精炼结果时直接成文，不重复精炼或再次删减。
原稿顺序、知识、案例、来源定位与用户选择的读听版本继续保留。

遵循 Markdown 规则，以单个 `#` 和 `## 重点` 开头。
原课程“纯文本标题、不用 `#`”的规则由统一格式取代。
重点后、知识正文前放参考文件清单，按原稿、课件、笔记和代码分类；
列出本次提供的全部材料及实际采用的相关文件，
使用 `[x]` 标识已使用、`[ ]` 标识未使用，不声称读过未读取的文件。
没有某类材料时省略该类，不生成空清单。

知识模块保持原稿顺序，使用连续编号，
例如 `## 一、缓存（L1-L12）`、`### 1.1 缓存的用途（L1-L5）`。
位置取自实际原稿，可引用多个区间；无法获取时说明定位缺口，
不捏造行号。每个模块和知识小节保留可追溯范围。

## 二、知识与例子的呈现

保留精炼结果中的带主语问句、必要的“本节关系”和教学解释。
概念解释用段落或要点，完整实操用有序步骤，
不把充分解释压缩为只有标题的提纲。

教学例子用引用块，优先用具体案例名，否则使用“案例”。
例子与对应原理之间用空引用行分隔，保持同一引用块：

```markdown
> 案例：<原稿中的例子及其解释>。
>
> 对应原理：<该例子说明的已有知识>。
```

流程、关系或调用链用文本说明加 Mermaid 代码块辅助理解。
若需要术语速查，放在全文最后并继续正文编号，
例如 `## 三、附录：术语速查与统一口径`；不在知识主线中插入字典。

## 三、版本与检查

阅读稿清晰连贯，口播稿适合口头表达；双稿分文件交付。
两者使用同一知识与来源，不因表达方式不同改变事实。
检查案例与知识绑定、行范围真实、来源标注完整、未凭空补写知识。
