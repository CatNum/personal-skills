# 文档编写

## 重点

- **目的决定内容**：结合材料与文档用途编写，统一格式按输出形式加载。
- **按需披露**：只读取当前任务的类型细则、格式规则和必要模板。
- **面试复盘**：在本 skill 内完成分析与成文；
  原稿清理由 `transcript-refine` 负责。

## 一、确认任务与输出

先区分用户需要的动作：

- **新写或实质改写**：根据已提供材料、已确认要求和对应细则组织内容。
  不编造事实、数字、经历或未确定的设计；缺少关键依据时指出缺口。
- **格式化已有文档**：保留原意、结构和已有结论，
  不自动重做面试评分、技术分析或扩写产品需求。
- **仅清理转写稿**：交给 `transcript-refine`，不套成文模板。
- **清理后复盘**：先由 `transcript-refine` 清理，
  再用本 skill 分析并生成新文档；沿用已确认的路径与格式，不重复询问。

所有类型默认 Markdown。仅面试复盘支持用户指定 HTML 或双格式；
读取 [HTML 复盘规则](references/interview-html.md) 并使用对应模板。
未指定格式时直接生成 Markdown，不要求先三选一。
其他类型需要 HTML 或其他格式时，说明当前技能范围并确认交付方式，
不自行套用面试 HTML 模板。

写入新文件或创建目录前，读取 `project-structure` 的统一命名规则，
按目标目录分配排序编号；本 skill 只确定主题与用途后缀。
用户明确指定完整路径时遵循其请求，更新已有文档时保留原路径。
涉及项目文档布局时再加载该 skill 的项目文档细则。

## 二、判断文档目的

优先依据用户明确指定的类型，其次依据文档实际目的，
最后参考文件名或目录名。只读取命中的类型细则：

| 文档目的 | 按需读取 |
| --- | --- |
| 博客：观点或经历 | [博客](references/blog.md) |
| ROADMAP：版本主要更新与特性总览 | [ROADMAP](references/roadmap.md) |
| PRD/产品：功能目标、使用方式与规则 | [产品文档](references/product.md) |
| 商业化：商业模式与收费规则 | [商业化](references/commercialization.md) |
| 设计：产品功能的实现方案与内部逻辑 | [设计文档](references/design.md) |
| 个人学习笔记 | [学习笔记](references/notes.md) |
| 课程学习材料：由转写稿精炼形成的阅读稿或口播稿 | [课程材料](references/course-material.md) |
| 术语表 | [术语表](references/glossary.md) |
| 面试复盘：评价、考点、回答改进与短板 | [面试复盘](references/interview-review.md) |

兼有多个目的时，只读取相关细则，以主要读者和主要问题确定主类型。
可独立维护的内容可拆分并互相链接。
涉及共用术语时额外读取术语表细则；同一功能的产品与设计引用同一定义。
类型不明确时保留原结构，仅做通用整理；
若类型会改变实质内容取舍，再向用户确认，不武断套模板。

## 三、成文规则

- **统一语义结构**：一个主标题，紧随其后的重点，
  清晰连续的正文层级。章节建议按需选用，不产生空章节或未填占位符。
- **面向读者成文**：正文呈现事实、判断与必要依据；核对过程留在工作上下文。
  - 已明确的日期、时长、身份、术语等直接写入；用户补充后更新对应内容，
    清理已解决的疑点与旧表述，不追加“由本人确认”“经用户核对”等编辑批注。
  - 推断写明依据和结论范围；未知信息指出具体缺口，集中说明共用限制。
  - 人物观点、问句和个人判断保留归属，避免转述成客观事实或已实施方案。
    来源存在冲突、会影响结论，或用户要求审计、溯源时，保留必要的来源与状态。
    角色身份等普通信息无需例行加“自述为”“据称”等限定。
  - 用户要求修改日志、核对清单或证据账本时，单独提供过程记录。
    其他成文任务的正文不自动增加确认记录、纠错经过或自证式说明。
- **内容边界**：产品文档不以技术方案已设计为前提；
  设计文档说明实现逻辑，主动使用文本说明与 Mermaid 表达关系和流程。
  商业化策略单独维护，PRD 引用其功能影响。
- **可读性**：每段一个主题，独立主题分段。
  并列要点用无序列表，有顺序或依赖的步骤用有序列表。
  加粗突出关键短语，行内代码标识精确技术文本，引用块标识原文，
  链接连接来源与相关文档。介绍字段、函数时解释含义与作用。
- **格式按需加载**：生成或整理 Markdown 时必须读取
  [Markdown 规则](references/markdown.md)，执行标题编号、源码换行、
  代码块、表格、Mermaid 及旧文更新规则。
  HTML 使用语义标题、列表、强调与引用，不把 Markdown 标记作为正文输出。
- **保留旧文**：默认保留原意、事实、结构与标题深度，
  仅在结构错误或用户要求重组时作必要调整，并检查受影响的文内链接。

## 四、输出与自检

用户要求直接给文档且未要求解释时，只输出最终文档。
编辑文件、讨论写法或修改 skill 时，按请求说明改动、验证与剩余缺口。
用户明确要求贴全文或只输出文档时遵循其要求。

交付前检查：类型与格式是否正确，相关细则是否按需加载，
内容是否有依据，事实、推断与未知是否区分，正文是否混入无关核对过程，
标题与重点是否唯一，编号是否连续，
分段、分点与强调是否便于阅读，源码或页面是否需要横向滚动，
旧文语义与引用是否保留，是否存在空章节、占位符或虚构内容。
面试复盘额外检查证据、评分与改进答案是否区分，
双格式是否来自同一次分析且内容一致。
