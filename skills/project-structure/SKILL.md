# 文件与目录结构管理

## 重点

- **统一命名**：普通文件和文件夹使用数字编号、英文句点与一个空格。
- **稳定顺序**：在目标目录内分配编号，新增时保留已有编号与路径。
- **按需加载**：一般命名遵循本文件；项目文档布局另读 `references/`。

## 一、范围与入口

管理用户指定范围内的文件、目录及引用；不再仅限于 `docs/`。
先确认目标路径和本次操作范围，不把 skill 所在仓库当成目标项目。
创建一个输出文件时只处理该输出，不借机重命名来源和整个目录。
仅修改文件正文时沿用原路径，不触发批量编号。

新建、检查、命名或整理普通文件与文件夹时，执行以下统一规则。
涉及项目 `docs/` 的布局、ROADMAP、PRD 或技术方案的配对时，
额外读取 [项目文档布局](references/project-docs.md)。
正文编写与排版由 `document-writing` 等相应 skill 负责。

## 二、统一编号规则

- **格式**：使用 `00. 名称`、`01. 名称`、`02. 名称`，
  文件保留扩展名，如 `00. 用户登录.md`。
  从零开始，至少两位，不足两位补零；分隔符是英文句点 `.`，
  后面必须恰有一个普通半角空格，不能写成 `00.名称` 或 `00、名称`。
- **目录内排序**：每个父目录独立编号，进入子目录后重新分配。
  同一父目录中的普通文件与子目录共用序列，默认不占用同一编号。
  编号体现用户指定顺序；未指定时按已有组织或任务的自然顺序安排。
- **保持稳定**：新建空目录内从 `00` 起；已有编号时从最大编号后追加，
  不因删除或中间空号自动补位，不自动重排旧项。
  用户明确要求插入、重新排序或统一整理旧项时，才调整已有编号和引用。
  项目配对文档等特殊关联按相应细则保留对应编号。
- **扩展名与派生稿**：先确定名称主体，再分配目标目录中的编号。
  从来源名派生时先去掉已有的排序前缀和扩展名，
  再追加“清理”“阅读稿”“复盘”等用途，避免双重编号。
  同一内容同时输出 `.md` 与 `.html` 时共用编号和主干，
  它们是同一文档的两种格式，不占两个顺序位置。
- **编号容量**：新建一批超过一百项时，从开始就统一使用足够的位数，
  如 `000. 名称`。已有两位编号需要扩容时，先说明固定宽度排序需要
  统一补零及路径更新；不要直接混用位宽并声称字典序仍稳定。
  获得重新编号的授权前保留旧路径。

例如，目标目录已有 `00. 面试记录.md` 和 `01. 资料/`，
新增清理稿使用 `02. 面试记录-清理.md`。
若再生成同一复盘的两种格式，可使用 `03. 面试记录-复盘.md`
与 `03. 面试记录-复盘.html`。

## 三、固定名称与优先级

- 用户明确指定的完整路径或名称优先；只有主题而非精确文件名时，
  仍按统一规则分配编号。
- 工具、运行时、构建、导入或协议要求固定名称的路径保留原名，
  如 `SKILL.md`、`README.md`、`AGENTS.md`、`package.json`、
  `.git/`、`docs/`、skill 入口目录，以及已被程序依赖的源码路径。
  普通资料文件可保留语义主干后编号；不能通过编号破坏运行和自动发现。
- 已存在的外部材料与被引用路径默认保留；
  整理旧项前检查调用方和相对链接，不能仅凭名称判断可安全改名。

## 四、操作与自检

1. 检查目标目录、现有编号、固定名称、相关引用及用户指定路径。
   判断是新增、更新，还是明确要求重命名与重排。
2. 新增时按统一规则分配编号；更新时使用原路径。
   整理旧项先列出旧路径到新路径的映射，再执行范围内可确定的改名。
3. 有重名、不同内容的目标已存在、编号或配对顺序冲突时，
   先保留文件并列出冲突；没有明确处理依据时再向用户确认。
   新建产物可分配新的末尾编号，不覆盖已有内容。
4. 改名或移动后，同步更新受影响的配对文件、相对链接及配置引用。
   带空格的路径在命令中正确引用，在 Markdown 链接中按语法处理。
5. 交付实际路径与必要的迁移映射。核对编号、句点后的单个空格、
   排序结果、固定名称例外及引用有效性。
   只要求检查时报告问题，不执行重命名。
