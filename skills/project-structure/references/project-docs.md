# 项目文档布局

## 重点

- **固定路径**：项目文档在 `docs/` 下，保留既有三类目录与 ROADMAP 路径。
- **一一配对**：PRD 与技术方案使用相同编号和主题主干。

## 一、目录与命名

```text
<项目根目录>/
└── docs/
    ├── 00. ROADMAP/
    │   └── 00. ROADMAP.md
    ├── 01. PRD/
    │   └── 00. 用户登录.md
    └── 02. ARCHITECTURE/
        └── 00. 用户登录的技术方案.md
```

三个目录名和 `00. ROADMAP/00. ROADMAP.md` 的路径固定。
`docs/` 是约定入口，保留原名；其他新增普通文件与目录遵循主 skill 的编号规则。

PRD 主题可使用实际功能名或版本名，不强制版本号；
其排序前缀遵循统一编号规则，不再使用旧规则中的“序号可省略”。
技术方案文件名由 PRD 文件名去掉 `.md` 后追加 `的技术方案.md`，
例如 `00. 用户登录.md` 对应 `00. 用户登录的技术方案.md`。

## 二、配对操作

- 创建 PRD 时同时创建对应技术方案；从技术方案开始时，
  也保证对应 PRD 存在。配对文件保留完全相同的编号与主题主干。
  新增一对时检查两个目录，选择高于两边已用最大编号的下一编号，
  避免同一编号指向不同功能。
- 补齐已有文档的缺失配对时沿用已有编号；若该编号已被其他主题占用，
  报告冲突，不静默改动其他配对。
- 尚无内容时，配对文件只说明对应关系与待补充状态，
  不编造需求、架构、接口或技术决策。
- 移动或重命名 PRD 时，同步修改配对方案及相关链接。
  检查时双向核对缺失、重名和错配，保留旧文内容。
  用户只要求审查时不改名；要求修复时处理可确定的问题，
  冲突或配对关系不明确时先列出并确认处理方式。
