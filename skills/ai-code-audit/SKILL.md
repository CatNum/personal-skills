# AI 代码隐患检查与修复

检查正常路径之外的隐形问题，以系统约束与失效机制分类。默认完成证据定位、最小修复和针对性验证；用户明确只要求审查时只报告。AI 来源是检查背景，不是缺陷证据。

## 通用问题分类

| 类别 | 核心约束 | 典型失效机制 |
|---|---|---|
| 性能与依赖 | 关键路径只等待必需工作 | 无必要串行、冗余调用、过度同步、非关键依赖阻塞 |
| 状态与并发 | 结果属于当前上下文，状态迁移有序 | 乱序覆盖、重入、失效结果回填、取消与清理遗漏 |
| 一致性与提交语义 | 关联数据满足不变量，提交结果被准确表达 | 版本混用、部分提交、未知结果误判、重复副作用 |
| 身份与缓存 | 授权可信，缓存归属和有效性明确 | 缓存替代身份、跨上下文泄漏、失效策略缺失 |
| 交互与可观测性 | 可见状态与真实执行状态一致 | 反馈滞后、状态耦合、错误吞没、成功或失败误报 |
| 业务与运行边界 | 实现满足真实契约与环境限制 | 示例值冒充事实、输入越界、权限遗漏、资源泄漏、环境假设失效 |

各类别的检查方法、修复原则和验证维度见 [分类细则](references/hidden-problems.md)。类别可以重叠，按根因归类，不按某个页面或功能名称建目录。

## 执行流程

1. **明确范围与约束**：读取目标项目规则和工作区差异，保留其他改动。确认业务成功条件、可信上下文、数据不变量和允许的副作用。仅影响业务判断的缺失信息需要询问。
2. **建立证据**：追踪入口、依赖、状态变更、提交确认与结果消费。记录实际调用关系和必要测量，区分已复现、代码可证明、待验证假设；不把推测扩展成全系统结论。
3. **分类与排序**：按上表选择相关检查。优先处理越权、数据丢失、重复副作用和错误提交语义，再处理性能与反馈；不机械检查所有类别。
4. **保持约束后修复**：先用可重复实验或行为测试验证失效，再做授权范围内的最小改动。并行、缓存、局部更新和重试都须有正确性前提；依赖缺失的服务端能力时补齐实现或明确未解决边界。
5. **验证与报告**：验证原失效机制及受影响边界，执行项目要求的检查。报告类别、证据、影响、根因、修复、验证结果与限制；区分本地验证、线上验证和发布状态。只在用户授权范围内部署、提交、推送或修改真实数据。

## 修复时必须保持的约束

- 独立工作可以并行；有因果或版本依赖的操作保留顺序、事务、一致快照或版本校验。局部更新须有可信提交结果与匹配基线。
- 异步结果绑定可信上下文与生命周期；消费前检查归属和有效性。互斥须覆盖所有入口，清理不释放其他操作的锁，也不取消未知提交的防重约束。
- 区分明确成功、明确未提交和结果未知；后续同步失败不能改变已确认的提交事实。非幂等操作的未知结果先核实，不能盲目重发。
- 区分有效身份、明确未认证和身份读取失败。缓存仅用于展示或读取加速，不授予权限；缓存异常不改变已确认业务结果。
- 反馈对应真实阶段，非关键信息独立失败；不靠隐藏等待状态、伪造数据或提前报成功掩盖问题。
- 编译、静态检查和既有测试通过不证明所有边界正确。按证据补充异常、乱序、重入和生命周期验证；无法验证的结论保留限制。

## 知识沉淀规则

技能中仅保存**问题类别、失效机制、适用条件、核心约束、检查方法、修复原则与通用验证维度**。新发现先归入已有类别，只有机制存在实质区别时才扩展分类。

具体项目名、业务对象、故障经过、实现代码、账号、接口地址、日志、耗时及单次测试结果不写入技能包。具体发现作为本次任务输出；需要落盘时按目标项目的记录规范处理，不自动追加到本技能。

介绍具体字段或函数时解释名称含义与实际作用。持续维护只更新可复用规则，保留类别间的区别与适用前提。

通用评估条件见 [evals/scenarios.json](evals/scenarios.json)，用于构造隔离验证，不是历史故障或已执行结果。
